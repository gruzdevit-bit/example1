# Описание интерфейсов

Все страницы отдаются как HTML (Jinja2). Формы отправляются методом POST с полем `csrf_token`. Успешные действия завершаются редиректом `303` на список. Ошибки валидации возвращают ту же страницу с сообщением. Для действий с чужими данными — `403`, для отсутствующей записи — `404`.

Аутентификация упрощённая: `POST /login` c `user_id` записывает подписанную куку `substitution_session`, пароля нет.

## Маршруты

| Метод и путь | Назначение | Параметры | Ответ |
|---|---|---|---|
| GET `/health` | Проверка живости | — | 200, `ok` |
| GET `/` | Входная страница | — | 200 |
| GET `/login` | Выбор текущего пользователя | — | HTML |
| POST `/login` | Запомнить пользователя в куке | `user_id`, `csrf_token` | 303 `/substitutions` |
| POST `/logout` | Выход | `csrf_token` | 303 `/login` |
| GET `/substitutions` | Мои роли, список замещений, переданные мне роли | `status=all\|active\|planned\|completed\|revoked`, `ok` | HTML |
| GET `/substitutions/new` | Форма настройки замещения | — | HTML |
| POST `/substitutions` | Создать строки замещений | `date_from`, `date_to`, `role_ids`, `deputies_<role_id>` (несколько значений), `csrf_token` | 303 `/substitutions?ok=created` или 400/403 |
| GET `/substitutions/{id}` | Карточка и история по роли | — | HTML, 403 или 404 |
| POST `/substitutions/{id}/revoke` | Отозвать строку «роль — заместитель» | `csrf_token` | 303 или 403/404 |
| POST `/roles/{role_id}/revoke` | Отозвать роль целиком | `csrf_token` | 303 или 403 |
| POST `/substitutions/revoke-all` | Отозвать все замещения пользователя | `csrf_token` | 303 |
| GET `/delegated` | Роли, переданные текущему пользователю | — | HTML |
| GET `/users` | Пользователи и роли | `ok` | HTML |
| POST `/users` | Создать пользователя | `full_name`, `email`, `csrf_token` | 303 `/users?ok=user_created` или 400 |
| POST `/roles` | Создать роль | `name`, `description`, `csrf_token` | 303 `/users?ok=role_created` или 400 |
| POST `/users/{id}/roles` | Заменить набор ролей пользователя | `role_ids` (несколько значений), `csrf_token` | 303 `/users?ok=roles_saved` или 400/404 |

## Серверная валидация создания замещения

- `date_from` и `date_to` обязательны и должны быть корректными датами.
- `date_to` не может быть раньше `date_from`.
- Должна быть выбрана хотя бы одна роль.
- Все выбранные роли должны принадлежать текущему пользователю (иначе 403).
- Для каждой выбранной роли должен быть выбран хотя бы один заместитель.
- Заместитель должен существовать; заместителем нельзя выбрать самого себя (403).
- Период хранится в формате `YYYY-MM-DD`, дата окончания включается в период.

## Расчёт статусов и доступа

Статус строки вычисляется при чтении по текущей дате UTC:

- `revoked_at` заполнено → «отозвано»;
- сегодня < `date_from` → «запланировано»;
- `date_from` ≤ сегодня ≤ `date_to` → «активно»;
- сегодня > `date_to` → «завершено».

Роль недоступна владельцу, если по ней есть хотя бы одна активная строка. Заместитель имеет доступ к роли только при наличии активной строки, где он указан. Отзыв записывает `revoked_at` и не удаляет строку, поэтому история сохраняется.

Дату для демонстрации можно зафиксировать переменной `SUBSTITUTION_TODAY` (ISO). На стенде она не задаётся.
